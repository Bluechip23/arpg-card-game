Ordered refactor plan derived from `AUDIT.md`. ## Step 0 — Baseline and the verification gates (first commit of Phase 3)

Add one script, `tools/refactor_gate.sh`, that captures a snapshot into a directory and (optionally) diffs it against a baseline. I will commit it first so every later step uses the identical procedure. Two tiers:

**Quick gate (~2–3 min) — after every step**
```
godot --headless --path . --script tests/test_parse_all.gd          # 132 scripts parse
godot --headless --path . --script tests/test_sim_determinism.gd    # harness still deterministic
godot --headless --path . --script tests/sim/dump_catalog.gd -- --out=$OUT/catalog.json   # every card, item, enemy stat, sphere node, build component
godot --headless --quiet --path . --script tests/sim/run_sim.gd -- --sweep=tests/sim/sweeps/example.txt --out=$OUT/sim     # baseline/hand_check × random/greedy/scripted, 41 runs
godot --headless --quiet --path . --script tests/sim/run_sim.gd -- --sweep=$OUT/quick_designed.txt --out=$OUT/sim          # first 2 jobs of each character's *_designed.txt at seeds 1-10 (100 runs)
```
`quick_designed.txt` is generated by the gate from the five `tests/sim/sweeps/<char>_designed.txt` files with `seeds=1-100` rewritten to `seeds=1-10` (the stored sweeps are not edited).

**Full gate (~30 min on 4 shards) — after each phase (A, B, C, D) and before every push**
```
tools/sim_analysis/run_sweep.sh $OUT/full_designed.txt     4 $OUT/sim   # all five *_designed.txt at seeds 1-20  (≈3,000 runs)  → "items" and "enemy power" through the designed builds
tools/sim_analysis/run_sweep.sh $OUT/combos_10.txt         4 $OUT/sim   # combos.txt at seeds 1-10                 (≈2,300 runs)  → "combos"
tools/sim_analysis/run_sweep.sh $OUT/build_divergence_20.txt 4 $OUT/sim # build_divergence.txt at seeds 1-20       (≈740 runs)
tools/sim_analysis/run_sweep.sh $OUT/enemy_strategy_10.txt 4 $OUT/sim   # enemy_strategy.txt at seeds 1-10         (≈1,000 runs) → every acting enemy
tests/run_all.sh -j 4 -o $OUT/tests                                     # the 120 SceneTree tests (incl. test_sim_audit, ~4 min)
```
**Comparison:** `diff -r --exclude=stamp.txt --exclude=logs $BASELINE $OUT` must be **empty**. Per-seed CSVs, `summary.csv`, `aggregate.csv`, `loadout.json` and `catalog.json` are byte-compared (the harness is deterministic per seed, so "any difference IS the change" — `docs/sim/README.md`). `stamp.txt` is the code hash and differs by design. `tests/run_all.sh` must report the same PASS/FAIL set as the baseline (I will record the baseline's set; today `test_parse_all` and `test_sim_determinism` pass; I have not yet run the other 118).

**Seeds note.** The stored sweeps use 100 seeds (several hours each); for a byte-identity check 10–20 seeds per job already exercise every code path the job touches, and the full gate still runs ≈7,000 combats. If you prefer the full 100-seed `combos.txt`/`card_power.txt`, say so and I will budget ~3 h per full gate instead.

**What the sim cannot see.** Town, menus, inventory UI, hover/tooltips, labels, the AOE preview, lighting and import settings never run in the headless sim. Steps marked **[UI-only]** below are verified by the parse test, the `tests/test_*` suite (several boot `town.tscn`, `character_panel`, `sandbox`, `hud`) and a note asking you to eyeball the named screen in the editor.

Baseline capture: `tools/refactor_gate.sh snapshot sim_out/baseline` (quick + full), committed nowhere (git-ignored `sim_out/`), kept for the whole phase. Timing measured: one combat ≈ 0.8 s, engine start ≈ 2 s.
